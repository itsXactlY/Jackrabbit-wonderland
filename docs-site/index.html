A real Linux agent — on your unrooted phone

This is the complete, from-scratch build-and-deploy guide for running hermes-agent natively inside a rootless Linux VM (Podroid) on a stock, unrooted Android phone — wired straight into your Mazemaker memory pod over an encrypted PRO gateway. Zero hardcoded IPs. Zero baked secrets. Install the Mazemaker app and you get the PRO tier: full federation into your desktop's ~200k-memory graph.

The stack is six layers — pod, gateway, VM, agent, apps, pairing — and they build bottom-up. Skim the picture below, then start at Get started → Prerequisites.

The architecture

One phone, one desktop, one encrypted hop between them. The phone never learns an IP at build time and no binary ships a secret — everything is discovered (mDNS) or pasted once (keys).

Proven, not aspirational

Verified end-to-end on release builds: a Hermes chat on the phone called mazemaker_recall through the whole chain and returned a real memory in the graph's id + similarity format — top hit id=955714 @ 0.5624, confirmed non-hallucinated with mazemaker_get(955714).

Where to start

Get started

Host prerequisites — Podman, arm64 binfmt, JDK 17 + Android SDK, NVIDIA CDI — and the exact bottom-up build order.

The memory pod

Rootless Podman Quadlets: mcp, embedding-worker, pgvector, dream-worker. Secrets, the license gate, GPU, and the single published port.

The PRO gateway

TLS + token + AES over the loopback-only pod. Provision the cert, print the tiny base64 pairing code, advertise via mDNS.

Podroid — the VM

A rootless Alpine 3.23 squashfs on AVF/pKVM. Build the rootfs, bake hermes, grant the two AVF permissions, boot in ~6 s.

The three apps

Mazemaker 1.4.0, Podroid 1.2.5, thin-Hermes 0.2.0 — signed release builds, with the camera-16KB and R8 fixes that are load-bearing.

Pairing & verify

Paste the pod key, scan/paste the pairing code, watch the proxy bind, and run the end-to-end recall acceptance test.

Part of the Wonderland family

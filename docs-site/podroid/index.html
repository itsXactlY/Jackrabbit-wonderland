Podroid — the Linux VM

A rootless Alpine 3.23 squashfs + persistent ext4 overlay, OpenRC as PID 1, booted by crosvm inside Android's Virtualization Framework (AVF / pKVM). This is the shipping variant — not the older proot thin app. Source: ~/projects/jrwl-messenger/android/podroid.

Build the Alpine rootfs squashfs

build-rootfs/build-rootfs.sh (run inside Dockerfile.rootfs) apk adds the base system — alpine-base openrc podman crun fuse-overlayfs nftables dropbear curl ca-certificates shadow-uidmap slirp4netns aardvark-dns netavark python3 … — sets rootless uid-map caps, then bakes the hermes pod: the podroid-hermes and podroid-hermes-mcp OpenRC services, the hermes venv at /opt/hermes, and the seed files, all added to the boot runlevel.

python3 is mandatory

hermes-agent's api_server is a Python venv. A rootfs without python3 dies with exec: /opt/hermes/venv/bin/hermes: not found (dangling interpreter). Alpine 3.23.4 ships Python 3.12.13, matching the venv's pyvenv.cfg.

bash
cd ~/projects/jrwl-messenger/android/podroid
./build-all.sh rootfs
# → app/src/main/assets/alpine-rootfs.squashfs  (~384 MB)

Build + install the Podroid APK

bash
./build-all.sh              # build_rootfs (if stale) then ./gradlew assemble…
# com.excp.podroid 1.2.5 (versionCode 28)

DEV=<adb-serial>
adb -s $DEV install -r app/build/outputs/apk/release/app-release.apk

Grant the AVF permissions

AVF is gated behind two privileged permissions that are revoked on every reinstall. Without them crosvm can't open the TAP and the VM dead-ends (easily misread as TUNSETIFF EACCES).

bash
PKG=com.excp.podroid        # or .debug
adb -s $DEV shell pm grant $PKG android.permission.MANAGE_VIRTUAL_MACHINE
adb -s $DEV shell pm grant $PKG android.permission.USE_CUSTOM_VIRTUAL_MACHINE
adb -s $DEV shell am force-stop $PKG      # EngineHolder resolves the engine
adb -s $DEV shell monkey -p $PKG 1        #   once per process — relaunch

# Verify GRANTED (dumpsys lists *requested* perms even when not granted):
adb -s $DEV shell dumpsys package $PKG | grep -A1 VIRTUAL_MACHINE | grep granted=true

Boot the VM from the app. On AVF/pKVM it comes up in ~6 s; only fall back to QEMU/TCG emulation (~190 s) on non-KVM devices.

hermes-agent & the per-install key

hermes-agent 0.15.1 (Nous Research) runs inside the guest as an OpenAI-compatible api_server on :8088, forwarded to Android loopback. No key ships in anything. On first boot start.sh:

sh · /opt/hermes/start.sh
# generate a per-install key if absent, persist in the overlay
[ -s /opt/hermes/api_server.key ] || \
  python3 -c 'import secrets;print(secrets.token_hex(32))' > /opt/hermes/api_server.key
# seed config.template.yaml → config.yaml (openrouter_free, EMPTY api_key)

api_server enforces the key (no bearer → 401) and refuses to start with an empty key. Read it once to paste into the apps:

sh · in the Podroid terminal (guest)
cat /opt/hermes/api_server.key      # 64 hex chars

The model provider key (OpenRouter etc.) is likewise empty in the template — paste it into /opt/hermes/config.yaml. Nothing is baked into the binaries.

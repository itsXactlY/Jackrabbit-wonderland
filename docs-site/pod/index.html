The memory pod

The Mazemaker engine, running as a rootless Podman pod under Quadlet + systemd --user. It's the graph the phone will recall from. Only one port (:8765) is published; everything else is pod-internal.

Secrets, license, config

One-time setup. The license (a Pro/Enterprise JWT + its Ed25519 pubkey) is what unlocks the Postgres backend, ColBERT, REM, Insight and DAE — without it, mcp silently drops to the SQLite community tier and splits writes from the dream-worker.

bash
mkdir -p ~/.mazemaker/{data,pgvector-data,sockets}

# PG password as a rootless podman secret (both containers reference it)
printf '%s' "$(openssl rand -hex 24)" | podman secret create mazemaker_pg_password -

# License JWT + Ed25519 pubkey — required for the Postgres tier
cp <your>/license.jwt         ~/.mazemaker/license.jwt
cp <your>/jwt.v1.pub.ed25519  ~/.mazemaker/jwt.v1.pub.ed25519

# Backend + compute selectors
printf '[backend]\nkind = "postgres"\n' > ~/.mazemaker/db.toml
printf '[compute]\ndevice = "auto"\n'   > ~/.mazemaker/compute.toml

The Quadlet units

Units live in ~/.config/containers/systemd/. Images are local-only; .container.d/ drop-ins set Pull=never.

UnitImagePortRole
mazemaker.pod—8765 publishedpod, wonderland MCP front
mazemaker-mcp…-mcp:latest (:gpu on Pro)8000MCP server + neural-memory engine
mazemaker-embedding-worker…-embedding-worker:latest8766bge-m3 embeddings, GPU
mazemaker-pgvectorpgvector/pgvector:pg16-trixie5432Postgres + pgvector
mazemaker-license-client—8767license gate
mazemaker-dream-worker…-dream-worker:gpu—NREM / REM / Insight consolidation

Invariants baked into the units

  • AddDevice=nvidia.com/gpu=all on mcp + embedding + dream (stripped on non-CDI hosts).
  • MM_DREAM_DISABLED=1 on mcp — the in-pod dream loop is off so it doesn't fight the interactive path for the GPU; the dream-worker container consolidates instead.
  • MemoryMax: mcp 8G, pgvector 8G, embedding 6G (tuned on a 200k corpus; bump for >500k).
  • Only :8765 is published; it binds 0.0.0.0 for federation but authorization is the pre-shared peer_key — a LAN scanner sees the pod, can't sync.
Never prune untagged layers

The mazemaker-v2 images are local-only. podman image prune on untagged layers → crash-loop, because Pull=never can't refetch them. Re-tag by env signature if you must clean up.

Bring it up

bash
systemctl --user daemon-reload
systemctl --user start mazemaker-pod.service
systemctl --user status mazemaker-mcp.service     # wait for GpuRecall warm-up

# Smoke test — MCP is stateless JSON in/out, no SSE or session needed
curl -s -H 'Accept: application/json' -H 'Content-Type: application/json' \
  http://127.0.0.1:8765/mcp \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | head -c 400
# → 31 tools (mazemaker_recall, mazemaker_remember, …)
